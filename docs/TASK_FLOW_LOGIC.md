# 任务流与待办联动

任务流集合使用任务流名称。编辑时可添加步骤，也可用「加入已有待办」多选现有待办；待办仅保存 `taskId` 引用。流程图中同一个待办只出现一次，名称与完成状态以待办记录为准；删除整个任务流不会删除待办。一个待办仅归属一个任务流，跨集合协作使用关联连线，避免重复执行。

步骤顺序自动生成竖向箭头，由任务流编辑器管理。启动准备中的排序和时长在启动前保存，图与实际执行队列一致。已完成步骤不再加入本次队列；休息段不会重复插入。

连线保存与执行前均检查规范：不允许循环（包括「一起完成」与「接着做」混用形成的循环）、重复路径、交叉分支或汇合、重复待办、重复工作步骤、整个集合与其子任务的重复嵌套。「一起完成」作为一个逻辑集合，只能有一个前一步和一个下一步。旧文件中的非法流程也会被阻止启动，原数据保留供用户修改。

任务流每个工作段时间到后暂停计时，弹出「接下来做什么」。用户确认才更新完成状态；确认继续后启动下一段（含配置的休息）。选择稍后再做结束本次执行并保留已确认的完成状态。浮窗与沉浸模式使用相同事件；关闭弹窗可从浮窗「下一步」重新打开。

从流程图启动和进入后续任务使用 RinUI 弹窗，不切换到专注页。完成已有待办会通知首页、流程图及统计。专注记录仍由原计时器记录实际投入时间。

当前步骤可提前确认完成，计时只记录实际投入。排队待办若在首页提前完成，后续执行会跳过它；结束提示也会随关联状态刷新。

验证：`tests/test_task_relations.py` 检查关系规则与稳定身份；`tools/flow_execution_smoke.py` 使用隔离数据，通过真实 QML 点击与浮窗计时器验证多选待办、完成同步、后续任务、休息段及非法流程拦截。
