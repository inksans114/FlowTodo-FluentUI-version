# 打开后无操作闪退

截图中的繁体中文系统、双显卡和硬件配置不能直接证明闪退原因。软件打开后仍会进行更新检查和后台定时任务；需要实际日志才能定位。

## 收集证据

新版源码在导入 Qt 和可选识别库前启用诊断。重新打包后，每次启动会在 `%LOCALAPPDATA%\FlowTodo\logs` 写入独立的 `runtime-*.log`，保留最近十次启动。设置 `FLOWTODO_DATA_DIR` 时，日志位于该数据目录的同级 `logs`；目录不可写时回退到 `%TEMP%\FlowTodo\logs`。

记录内容包括启动阶段、图形渲染环境开关、Python 未处理异常、后台线程未处理异常、Qt 消息及 faulthandler 能捕获的原生故障。系统直接终止进程等情况可能没有完整堆栈，不能承诺所有闪退都能捕获。不要仅凭日志末行推断根因。

1. 让用户正常启动，复现后发送最近的日志，说明从打开到退出大约几秒、版本号及是否每次必现。
2. 在完全解压后的程序目录，双击 `start_compatibility.bat` 再测试。它仅对本次进程启用软件渲染；不会清除任务或设置。退出后窗口会显示退出码。旧版本也可单独复制此脚本到 EXE 旁测试，但旧 EXE 不会因此获得新版日志功能。
3. 对比两次结果和日志。如果兼容启动稳定，只能说明图形渲染路径值得排查，仍需结合故障模块确认。
4. 没有有效日志时，按 `Win + R` 输入 `perfmon /rel`，打开对应时间的应用程序故障，提供程序版本、故障模块名称、异常代码。也可在事件查看器 → Windows 日志 → 应用程序中查看对应的 Application Error。

日志不主动收集账号令牌、完整环境变量、任务或 AI 对话，但异常和 Qt 输出可能包含本机路径等信息；分享前检查内容。

当前变更提供排查手段，尚未在反馈用户的电脑上复现或确认根因。不要让用户先删除数据或重装系统。
